# 기상특보 가능성

여러 기상 예보를 3시간마다 자동으로 모아 **지역별 기상특보 발효 가능성(%)과 예상 시간대**를 보여 주는 웹/앱(PWA)입니다.
비상근무 대비가 필요한 공직자·공공기관 직원을 위한 공개 서비스이며, 서버 비용 없이 GitHub Actions + GitHub Pages 만으로 돌아갑니다.

> **참고용입니다. 공식 특보·예비특보가 항상 우선합니다.**
> 실제 특보는 예보관이 관측과 영향을 종합해 발표하므로 계산 결과와 다를 수 있습니다.

- 대상 지역(1차): 전남 22개 시·군 + 보성(벌교) — `config/regions.json`
- 대상 특보: 호우·강풍·대설·한파·폭염(주의보/경보/중대경보)·열대야 (태풍은 기상청 발표만 반영) — `config/thresholds.json`
- 비교 자료: 기상청 단기예보 + Open-Meteo 의 ECMWF · GFS · ICON · JMA — `config/settings.json`
- **실시간 자료**: 특보·예비특보, 지금 날씨(초단기실황), 앞으로 6시간(초단기예보)은 5분 간격으로 따로 받아 화면에 덮어 보여 주고,
  비구름 레이더(기상청 합성영상)는 화면이 직접 불러옵니다 — 아래 [실시간 자료](#실시간-자료)
- **철도 특보 지도**(`rail.html`): 전국 철도 노선·역 위에 지금 발효 중인 특보·예비특보 구역을 표시하고,
  전날까지의 코레일 공식 운행 기록으로 “특보 구간을 지난 열차가 얼마나 늦었나”를 집계합니다 — 아래 [철도 특보 지도](#철도-특보-지도)

## 구성

```
GitHub Actions (3시간마다)                                   GitHub Pages
┌─────────────────────────────────────────────┐            ┌──────────────────────┐
│ 수집  teukbo/sources/                        │            │ web/ (HTML·CSS·JS)   │
│   open_meteo.py    Open-Meteo 수치모델        │  배포       │  + data/latest.json  │
│   kma_forecast.py  기상청 단기예보            │ ─────────▶ │  + data/detail/*.json│
│   kma_warnings.py  기상청 특보·예비특보        │            │  + data/accuracy.json│
│ 계산  indicators → assess → scoring          │            └──────────────────────┘
│ 저장  data/history/날짜.json (커밋, 누적)      │               PWA: manifest + sw.js
│ 집계  data/accuracy.json (적중률)             │
└─────────────────────────────────────────────┘
```

| 폴더 | 내용 |
|---|---|
| `config/` | 지역, 특보 기준, 계산 파라미터 (코드 수정 없이 여기만 고치면 됩니다) |
| `teukbo/` | 수집·계산·저장 파이썬 패키지 (표준 라이브러리만 사용) |
| `tests/` | 단위 테스트 (`python3 -m unittest discover -s tests -t .`) |
| `web/` | 정적 웹 화면과 PWA 설정 (`web/geo/` 는 지도용 지리 자료 — [web/geo/README.md](web/geo/README.md)) |
| `data/` | 누적 이력, 적중률, 열차 지연 집계 — [data/README.md](data/README.md) |
| `tools/` | 한 번만 쓰는 도구 (`build_geodata.py`: 지도용 지리 자료 만들기) |
| `.github/workflows/` | `collect.yml`(3시간마다 수집·계산·배포), `live.yml`(5분마다 실시간 자료), `test.yml`(테스트) |

## 처음 설정하기

1. **이 브랜치를 `main` 에 합칩니다.** 예약 실행(cron)은 기본 브랜치에서만 동작합니다.
   GitHub Pages 무료 사용을 위해 저장소는 Public 이어야 합니다.
2. **인증키 발급** (없어도 Open-Meteo 만으로 계산은 되지만, 발효 특보·예비특보가 “확인 불가”로 나옵니다)
   - [공공데이터포털](https://www.data.go.kr) 에서 두 API 를 활용신청합니다(자동승인).
     - [기상청_단기예보 조회서비스](https://www.data.go.kr/data/15084084/openapi.do)
     - [기상청_기상특보 조회서비스](https://www.data.go.kr/data/15000415/openapi.do)
   - (권장) [기상청 API허브](https://apihub.kma.go.kr) 에도 가입해 **단기예보 조회**, **특보현황 조회**를 각각 활용신청합니다.
     공공데이터포털이 GitHub Actions(해외 IP)에서 막히거나 응답하지 않을 때 자동으로 이쪽을 씁니다.
3. **GitHub Secrets 등록** — 저장소 Settings → Secrets and variables → Actions → New repository secret

   | 이름 | 값 |
   |---|---|
   | `DATA_GO_KR_SERVICE_KEY` | 공공데이터포털 일반 인증키 (Decoding·Encoding 어느 쪽이든 됩니다) |
   | `KMA_APIHUB_KEY` | 기상청 API허브 인증키 (선택) |

   인증키는 코드·설정 파일에 쓰지 않습니다. 로그에도 `***` 로 가려집니다.
4. **GitHub Pages 켜기** — Settings → Pages → Build and deployment → Source: **GitHub Actions**
5. **첫 실행** — Actions 탭 → “수집·계산·배포” → Run workflow.
   끝나면 `https://<계정>.github.io/<저장소 이름>/` 에서 볼 수 있습니다. 실행 요약(Summary)에 출처별 성공 여부가 표시됩니다.

이후에는 기상청 단기예보 발표 직후(02:25, 05:25, … 23:25 KST 무렵)마다 자동으로 갱신됩니다.

## GitHub 없이 내 컴퓨터에서만 쓰기

파이썬만 설치되어 있으면 됩니다. 윈도우는 `start.bat`, 맥은 `start.command` 를 두 번 누르세요.

- 처음 한 번 공공데이터포털 인증키를 물어보고 `local_keys.txt` 에 저장합니다(이 컴퓨터에만 남고 커밋되지 않음).
- 창을 열어 두는 동안 3시간마다 다시 수집하고, 브라우저로 `http://127.0.0.1:8000/` 을 엽니다.
- 화면은 **그 컴퓨터에서만** 열립니다. 다른 사람이나 휴대폰에서 보려면 GitHub Pages 배포(위 “처음 설정하기”)가 필요합니다.
- 인터넷·인증키 없이 화면만 보려면 `start.bat --demo` (가상 자료).

## 내 컴퓨터에서 확인하기 (개발용)

파이썬 3.10 이상만 있으면 됩니다(설치할 패키지 없음).

```bash
python3 -m teukbo.run --demo
```

```bash
python3 -m teukbo.site --data-dir data-demo
```

```bash
python3 -m http.server -d _site 8000
```

`--demo` 는 네트워크 없이 가상의 호우·강풍 시나리오를 만들어 화면과 계산을 점검합니다(화면에 “데모” 표시, 실제 이력에는 기록되지 않음).
실제 수집은 `DATA_GO_KR_SERVICE_KEY=... python3 -m teukbo.run` 후 `python3 -m teukbo.site` 입니다.

```bash
python3 -m unittest discover -s tests -t .
```

출처에 실제로 접속되는지(인증키·모델 이름 확인)만 보려면 — 아무것도 저장하지 않습니다:

```bash
python3 -m teukbo.check
```

## 설정 파일

### `config/regions.json` — 지역

지역을 추가하려면 `regions` 에 항목을 하나 더 넣으면 됩니다.

```json
{"id": "suncheon", "name": "순천시", "group": "jeonnam", "lat": 34.9507, "lon": 127.4872, "nx": 70, "ny": 70,
 "warning_zones": [{"code": "L1051200", "name": "순천"}],
 "params": {"tropical_night_min": 26}}
```

- `nx`, `ny`(단기예보 격자)는 `python3 -m teukbo.grid <위도> <경도>` 로 계산합니다.
- `warning_zones` 는 기상청 특보구역 코드·이름입니다(공공데이터포털 기상특보 조회서비스 첨부 「특보구역코드안내」).
  2026-05-31 구역 세분화로 한 시·군이 여러 구역으로 나뉜 곳(고흥북부/고흥남부 등)은 모두 적어 두었고,
  그중 한 곳이라도 특보가 있으면 그 시·군의 특보로 표시합니다. 여수의 거문도.초도, 신안의 흑산도.홍도도 포함됩니다.
- 다른 도를 추가할 때는 `zone_groups` 에 그 도의 코드·이름을 추가합니다(도 전체에 내려진 특보를 연결하는 데 사용).

### `config/thresholds.json` — 특보 기준

기준값은 코드에 없고 모두 이 파일에서 읽습니다. 출처는 **기상법 시행령 [별표 1] (2026. 6. 30. 시행)** 과
[날씨누리 기상특보 발표기준](https://www.weather.go.kr/w/forecast/guide/standard.do)입니다(2026-11-12 확인).

| 특보 | 주의보 | 경보 |
|---|---|---|
| 호우 | 3시간 60mm 이상 또는 12시간 110mm 이상 | 3시간 90mm 이상 또는 12시간 180mm 이상 |
| 강풍(육상) | 풍속 14m/s 이상 또는 순간풍속 20m/s 이상 | 풍속 21m/s 이상 또는 순간풍속 26m/s 이상 |
| 대설 | 24시간 신적설 5cm 이상 | 24시간 신적설 20cm 이상 |
| 한파(10~4월) | 아침 최저기온이 전날보다 10℃ 이상 하강해 3℃ 이하(+평년보다 3℃ 낮음) 또는 -12℃ 이하 2일 이상 | 15℃ 이상 하강해 3℃ 이하(+평년보다 3℃ 낮음) 또는 -15℃ 이하 2일 이상 |
| 폭염 | 일 최고 체감온도 33℃ 이상 2일 이상 | 35℃ 이상 2일 이상 |
| 폭염중대경보(2026 신설) | — | 체감온도 35℃ 이상이 2일 이상 관측된 지역에서, 일 최고 체감온도 38℃ 이상 또는 일 최고기온 **39℃ 이상** |
| 열대야(2026 신설) | 폭염주의보 수준이 예상되면서 밤 최저기온이 지역별 기준(25℃, 해안·대도시 26℃) 이상 | — |
| 태풍 | 계산하지 않고 기상청 발표만 반영 | 〃 |

기준이 바뀌면 이 파일의 값과 `version`, `checked_at` 만 고치면 됩니다. 구조 설명은 파일 맨 위 `_doc` 에 있습니다.

### `config/settings.json` — 계산·수집 파라미터

예측 범위(48시간), 비교할 모델 목록, 가능성 계산식의 가중치, 등급 구간, 재시도 횟수 등.

## 계산 방법 (1단계: 규칙 기반)

1. 자료(모델)마다 시간별 예측값으로 지표를 만듭니다: 3·12시간 누적 강수, 24시간 신적설, 시간별 풍속·순간풍속,
   일 최고 체감온도(기상청 여름철 체감온도 산출식), 밤·아침 최저기온 등.
2. 향후 48시간 안에서 특보별로
   - **도달률** = 자료별 최대 예측값 ÷ 기준값 (기온 지표와 ‘이하’ 기준은 `baseline` 으로 0% 지점을 옮겨 계산)
   - **초과 모델 비율** = 기준을 넘긴 자료 수 ÷ 전체 자료 수
   - **가능성(%)** = 50% × 초과 비율 + 20% × 점수(최대 도달률) + 30% × 점수(평균 도달률)
     — 점수는 도달률 50% 이하 0점, 100% 이상 만점, 사이는 비례. 식은 `teukbo/scoring.py` 의 `compute_probability()` 한 함수에 있습니다.
   - **예상 시간대** = 자료별로 기준을 처음 넘는 시각의 범위
3. 등급: 30% 미만 **낮음** · 30% 이상 **주의** · 60% 이상 **높음**.
   기상청 **예비특보**가 있으면 ‘높음’ 이상으로 올리고, 특보가 발표되어 있으면 **발효 중**으로 표시합니다.

## 적중률

`data/history` 에 쌓인 기록으로 매 회차 다시 집계합니다(`data/accuracy.json`, 웹에 표시).

- **사전 포착률**: 실제 발효된 특보 가운데, 발효 12·24시간 전 시점에 ‘주의’ 이상이었던 비율
- **오경보율**: ‘주의’ 이상(또는 ‘높음’)으로 표시한 예측 가운데, 이후 48시간 안에 실제 특보가 없었던 비율

기상청 발표를 반영하기 전의 **계산 등급**으로 비교합니다(예비특보로 올린 등급을 쓰면 계산식의 성능을 알 수 없으므로).

## 실시간 자료

가능성 계산(수치모델 비교)은 예보가 새로 나오는 3시간 간격이면 충분하지만, **특보 발효·해제와 지금 날씨는 빨리 반영되어야** 합니다.
그래서 가벼운 수집을 따로 돌립니다.

| 무엇 | 출처 | 반영까지 |
|---|---|---|
| 특보·예비특보 발효/해제 | 기상청 기상특보 조회서비스 | 보통 5~10분 |
| 지금 날씨 (기온·1시간 강수량·풍속·습도) | 기상청 초단기실황 (매시 정시 기준, 10분마다 갱신) | 보통 5~15분 |
| 앞으로 6시간 (시간별) | 기상청 초단기예보 (매시 30분 발표) | 발표 뒤 20~30분 |
| 비구름 레이더 | 기상청 레이더 합성영상 (5분 간격) — 화면이 기상청에서 직접 불러옴 | 관측 뒤 5~10분 |
| 실시간 열차 위치 | 한국철도공사 열차위치 화면을 그대로 끼워 보여 줌 | 코레일 화면 그대로 |

구조
```
live.yml (5분마다)  →  python3 -m teukbo.live  →  live.json  →  `live` 브랜치 (최신 한 벌만, 기록은 쌓지 않음)
화면(live.js)  →  https://raw.githubusercontent.com/<저장소>/live/live.json 을 2분마다 다시 읽어 latest.json 위에 덮어 그림
```

- **정확성 원칙**: 값마다 ‘확인 시각’을 따로 싣고, 화면은 30분(`config/settings.json` 의 `live.stale_after_minutes`)보다 오래된 실시간 값은 쓰지 않습니다.
  그때는 “실시간 갱신 지연”을 표시하고 3시간 주기 자료로 돌아갑니다. 조회에 실패하면 직전 값을 싣되 확인 시각은 바꾸지 않습니다(오래된 값을 새것처럼 보이지 않게).
- 화면의 등급 덮어쓰기(발효 중이면 ‘발효 중’, 예비특보면 최소 ‘높음’)는 서버 계산과 같은 규칙이며, 테스트가 두 결과가 같은지 확인합니다.
- **한계 — 엄밀한 실시간이 아닙니다.** GitHub 의 예약 실행은 5분이 가장 짧고 사정에 따라 수십 분 늦거나 건너뛸 수 있으며, 파일 전달에도 최대 5분이 걸립니다.
  1분 안팎의 반영과 안정성이 필요하면(실제 업무 판단에 쓰는 경우) 인증키를 보관하는 중계 서버(예: Cloudflare Workers 무료 요금제, 기관 내부 서버)에서
  `teukbo.live` 를 돌리고 `TEUKBO_LIVE_URL` 만 그 주소로 바꾸면 됩니다. 화면은 그대로 씁니다.
- 지금 날씨·6시간 예보는 설정한 지역(시·군청 위치 격자)만 받습니다. 호출 수: 지역 23곳 기준 하루 약 5천 건(공공데이터포털 개발계정 한도 1만 건 이내).
- 코레일 화면은 권한을 줄인 틀(`iframe sandbox`) 안에 그대로 보여 주며, 그 안의 열차 자료를 읽거나 가공하지 않습니다(브라우저가 막습니다).

## 철도 특보 지도

`https://<주소>/rail.html` — 화면 위쪽 탭 “철도 지도”.

| 무엇 | 어떻게 |
|---|---|
| 지도 | 기상청 특보구역(육상 235곳) 경계 위에 철도 노선·역을 직접 그립니다(외부 지도 서비스·인증키 없음). 진한 채움 = 경보, 옅은 채움 = 주의보, 빗금 = 예비특보, 점무늬 = 이 서비스가 계산한 가능성(전남) |
| 지금의 특보 | 3시간마다 받는 기상청 특보 현황 전문을 전국 구역 코드로 풀어 `data/warnings.json` 으로 배포 |
| 열차의 실시간 위치 | 우리 지도에는 **표시하지 않습니다.** 공개된 실시간 위치 자료가 없고, 코레일 열차위치 화면의 내부 주소는 외부 프로그램의 접근을 허용하지 않습니다. 대신 코레일의 공식 열차위치 화면을 지도 아래에 그대로 끼워 보여 줍니다(특보 지도와 겹쳐 그리거나 분석에 쓰지는 못함) |
| 열차 지연 통계 | 한국철도공사 「열차운행정보」(공공데이터포털, **전날까지만 제공**)의 계획·실제 시각으로 종착 지연을 계산하고, 열차가 정차한 역의 특보구역에 그 시각 특보가 있었는지와 묶어 집계 (`teukbo/rail.py`, `teukbo/rail_run.py`) |

- 공공데이터포털에서 [한국철도공사_열차운행정보](https://www.data.go.kr/data/15125762/openapi.do)를 활용신청해야 합니다(같은 `DATA_GO_KR_SERVICE_KEY` 사용).
  신청하지 않았거나 실패해도 기상 수집·배포에는 영향이 없습니다(해당 단계만 건너뜀).
- 처음에는 과거 59일치를 한 번에 12일씩(최대 6분) 나누어 채웁니다. 며칠 지나면 모두 채워지고 이후에는 하루치씩 늘어납니다.
- 전날 기록은 다음 날 새벽~오전에 올라옵니다(자정 직후에는 아직 없음). 올라오는 도중에 받았을 수 있으므로
  그날이 끝나고 하루가 더 지나기 전까지는 실행 때마다 다시 받아 달라진 내용을 반영합니다(`final: false`).
- **통계의 뜻**: 특보와 지연이 같은 때 있었다는 것만 보여 줍니다. 사고·고장·선로 작업 등 다른 원인이 섞여 있으므로
  “특보 때문에 늦었다”는 뜻이 아닙니다. 정차역 기준이라 정차하지 않고 지나간 구역의 특보는 반영되지 않습니다.
- 열차 종류(KTX·무궁화 등)는 공식 자료에 없어 열차번호 대역으로 나눕니다(`config/settings.json` 의 `rail.train_classes`).
- 광역전철(수도권 전철 등)은 운행 기록에 없어 통계에 포함되지 않습니다.

## 운영하면서 알아 둘 점

- **Open-Meteo 호출 한도는 접속 IP 기준**(하루 10,000회 등)입니다. GitHub Actions 는 여러 사용자가 IP 를 함께 쓰므로
  내 사용량과 무관하게 `429` 가 날 수 있습니다. 그 회차는 받은 자료만으로 계산하고 화면에 빠진 모델을 표시합니다.
  모든 예측 자료를 못 받으면 실행을 실패 처리하고 이전 배포를 그대로 둡니다(화면에는 “자료가 N시간 전 것” 경고).
- **공공데이터포털은 GitHub Actions(미국 IP)에서 간헐적으로 연결 시간 초과**가 보고되어 있습니다.
  `KMA_APIHUB_KEY` 를 등록해 두면 실패 시 자동으로 API허브로 넘어갑니다. API허브는 API 마다 활용신청이 필요합니다.
- **Open-Meteo 의 기상청(KMA) 수치모델은 2026-03-31 부로 갱신이 중단**되어 사용하지 않습니다.
  기상청 예측은 단기예보로 반영하고, 한반도를 5km 로 덮는 일본기상청 MSM 을 추가했습니다.
- **Open-Meteo 무료 API 는 비상업적 이용만 허용**합니다(광고·유료 구독이 붙으면 안 됨). 출처 표기(CC BY 4.0)는 화면 하단에 있습니다.
- 예약 실행은 GitHub 사정으로 수 분~수십 분 늦게 시작될 수 있습니다.
- 이력 파일은 하루 약 0.2MB 씩 늘어납니다(연 70MB 안팎). 열차 지연 집계(`data/rail/`)는 하루 약 0.1MB 입니다.

## 한계

- 수치모델은 좁은 지역의 집중호우·돌풍을 낮게 예측하는 경향이 있습니다. ‘낮음’이 안전을 뜻하지 않습니다.
- 시청·군청 위치의 지점 예측값을 씁니다. 같은 시·군 안에서도 산지·해안·섬은 다를 수 있습니다.
- 한파특보의 “평년값보다 3℃ 이상 낮을 때” 조건, 폭염중대경보의 “35℃ 이상 2일 관측” 선행 조건은 반영하지 못합니다
  (그만큼 가능성이 높게 나올 수 있음).
- 기상청 단기예보의 1시간 강수량은 “50mm 이상”까지만 구분되어, 그 이상의 극한 강수는 50mm 로 계산됩니다.
- 건조·풍랑·황사·폭풍해일 특보는 계산하지 않고 발효 여부만 표시합니다.

## 2단계 (자료가 쌓인 뒤)

- 누적 이력으로 가능성 보정(예: 로지스틱 회귀로 모델 예측 → 실제 발효 확률). `data/history` 의 `x`(모델별 극값)·`h.r`(도달률)·`a`(실제 특보)를 그대로 쓸 수 있습니다.
- 가능성 ‘높음’ 시 푸시 알림, 지역 전국 확대.
- 구글 플레이 등록(TWA 래핑): `/.well-known/assetlinks.json` 을 **도메인 최상위**에 두어야 하므로,
  `<계정>.github.io/<저장소>/` 형태의 주소로는 안 되고 사용자 사이트 저장소(`<계정>.github.io`)나 자체 도메인이 필요합니다.
